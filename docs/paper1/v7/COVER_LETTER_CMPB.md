# Cover letter — Computer Methods and Programs in Biomedicine

Dear Editors,

Please consider the enclosed original research article, "Hemoglyph: an offline, guideline-traceable laboratory-panel interpretation engine with 33,183 rules, 99.2% AI-drafted, and four methods for verifying it against its sources, executable invariants and a frontier LLM", for publication in *Computer Methods and Programs in Biomedicine*.

**Why this submission is appropriate for CMPB.** The paper presents demonstrable software and the computing methodology needed to trust it. Hemoglyph is an offline, single-process engine that ranks a differential diagnosis from a laboratory panel and attaches a rule identifier, threshold and source locator to every entry; its rule base of 33,183 executable rules was drafted at scale with large language models, and we treat that rule base as software to be verified. Four reproducible methods are described and released as engine-agnostic tools: property-based executable invariants (run in-process, as a black box on real panels given identically to the engine and an LLM, and as a verifier behind the LLM); a source-concordance protocol frozen before sampling, with an activity log that identifies which rules actually drive output; a hash-frozen one-shot benchmark on more than 20,000 public encounters with supervised, prevalence and blinded LLM comparators; and an audit of the audit (core sufficiency, mutation testing of the static detectors, transfer to a second LLM-written corpus). Engine (AGPL-3.0), rule registry (CC BY-SA 4.0), evaluation scripts, prompts, outputs and freeze manifests are public. This matches the journal's aims of formal computing methods and demonstrable software.

**What is known.** Rule-based laboratory decision support is traceable but hand-maintained and rarely evaluated outside its home institution; supervised models and LLMs scale but cannot be audited clause by clause, and LLM benchmarks in medicine have been criticised for unstable metrics, leakage and post-hoc selection. AI-assisted drafting now makes very large rule bases cheap to produce, but no method has been described for verifying them, and a dated search found no openly licensed, machine-executable rule set for laboratory-panel interpretation.

**What this study adds.** (i) An open, offline engine whose every output is source-traceable, deterministic (byte-identical on repeated runs) and unit-invariant on identical perturbed panels (top-5 unchanged in 40/40 versus 8/40 for a frontier LLM). (ii) An invariant suite that found a ranking defect which 353 adversarial vignettes had missed. (iii) A concordance protocol whose result is unfavourable to our own system—92% of sampled rules could not be checked from their locators and at least 7.5% were demonstrably discordant—and an activity log showing that 1.1% of rules carry the output; the methodological conclusion is that provenance granularity, not rule count, limits auditability. (iv) A frozen benchmark in which a failed quarantine round is reported, the untrained engine reaches recall@5 parity with a frontier LLM (60.7% vs 59.6%, p = 0.54), a prevalence baseline shows that the engine's contribution is ordering rather than coverage, and the engine's criteria, used as a verifier behind the LLM, remove 40% of its unsupported assertions at no recall cost; a pre-specified consensus arm is reported as a negative result. (v) An audit of the audit showing that the 335 audited core rules reproduce the primary results, that static detectors catch structural defects but not plausible wrong thresholds, and that a second LLM-written rule set shows the same defect classes.
